# Split

[![CI](https://github.com/andrew-markin/split/actions/workflows/ci.yml/badge.svg)](https://github.com/andrew-markin/split/actions/workflows/ci.yml)
[![License: GPL v3](https://img.shields.io/github/license/andrew-markin/split)](LICENSE)

Split is a simple open-source application for common expenses splitting. Splits can be easily shared by their URL addresses and therefore can be used for collaboration of a few people. With Split you can make sure that everything is counted and nothing is missed.

The application is available at [split.mayfleet.com](https://split.mayfleet.com/).

## Features

- Participants with transfer preferences, e.g. a bank account or a payment service to send money to.
- Patrons: a participant can pay for others, e.g. for family members, and their shares are added up.
- Expense categories with custom participation rates, so everyone pays only for what they share.
- Settlements calculated to the cent with as few transfers as possible, and completed transfers tracked. Settlements can be copied as text, e.g. to send them to a chat.
- Splits can be cloned, e.g. to start a new trip with the same participants and categories.
- Offline work: changes are kept in the browser and saved to the server once it's reachable again.
- Accessibility: keyboard navigation, screen reader support and text contrast meeting WCAG AA.
- English, Russian, Spanish, Brazilian Portuguese, German and French interface, light and dark color themes.

## How It Works

### Privacy

Every split is identified by a random secret stored in the URL fragment (the part after `#`). Browsers never send the fragment to servers, so the secret stays on the devices of people the link is shared with.

- The split data is compressed and encrypted with AES-GCM in the browser using a key derived from the secret. The backend stores the encrypted data along with its version, timestamps and the IP address of the last writer.
- The backend locates the data by an HMAC of the secret, so it can't restore the secret either.
- Anyone having the link can read and change the split, so share it carefully.
- For offline work and faster loading, the browser keeps local copies of up to 50 most recently opened splits in its IndexedDB. They are compressed and encrypted the same way, with a separate key derived from the secret, so they can't be read without the link. The link itself stays in the browser history though, so don't open private splits on shared devices.
- Besides the splits, the browser keeps only the selected theme and language and the hints already seen. The application uses no cookies, analytics, ads or third-party services.

The full privacy policy, including where the data is stored and how long the server logs are kept, is available in the application menu.

### Synchronization

The data is stored by the [Blobs](https://github.com/andrew-markin/blobs) backend as a single versioned blob per split. The backend notifies all connected clients about changes via Socket.IO.

Changes made on different devices at the same time are merged in the browser:

- Every field of every document has its own timestamp, and the latest change of the field wins.
- Removal of a document always wins over its changes.
- References between documents are checked after every merge, e.g. expenses of a removed participant are removed too.

## Development

### Prerequisites

- Node.js `^20.19.0` or `>=22.12.0`
- A running [Blobs](https://github.com/andrew-markin/blobs) backend

### Backend Setup

In the Blobs project directory, set `TOKEN_SECRET` in `.env`, then generate a token for the `split` bucket and start the server:

```sh
npm run token split
npm start
```

### Configuration

Copy `.env.example` to `.env.development.local` and adjust the values. Replace `VITE_BACKEND_TOKEN` with the one generated by your backend, since the token from the example is valid only for a specific `TOKEN_SECRET`:

| Variable             | Description                                                           |
| -------------------- | --------------------------------------------------------------------- |
| `VITE_BACKEND_URL`   | Blobs backend URL, e.g. `ws://localhost:3000`                         |
| `VITE_BACKEND_TOKEN` | Token for the `split` bucket generated by the backend                 |
| `VITE_CIPHER_SALT`   | Salt for deriving the storage anchors and keys from the split secrets |

These values are embedded into the public application bundle, so they aren't secrets. Changing `VITE_CIPHER_SALT` makes all existing splits inaccessible.

### Commands

```sh
npm install      # Install dependencies
npm run dev      # Start the development server at http://localhost:8085
npm test         # Run unit tests
npm run check    # Run linters and check formatting
npm run lint     # Fix linting issues
npm run format   # Format the source code
npm run audit    # Check production dependencies for vulnerabilities
npm run build    # Build for production into dist/
npm run pattern  # Regenerate the background pattern in public/pattern.svg
npm run og-image # Render the link preview image into public/og-image.png
npm run demo     # Record the demo video, e.g. npm run demo -- --locale ru
```

Integration tests of the synchronization run against the [Blobs](https://github.com/andrew-markin/blobs) project located next to this one or at `BLOBS_PATH`, and are skipped when it's missing. The project needs its dependencies installed, but not a running server: the tests start their own one with a temporary storage, token and salt.

The demo videos are recorded by a [script](scripts/demo/record.js) with no dependencies: it builds and serves the application, drives Google Chrome via the DevTools protocol, voices the captions by [Piper](https://github.com/rhasspy/piper), adds the [recorded sounds](scripts/demo/sounds/README.md) of the key presses and mouse clicks and encodes the result in Full HD by ffmpeg. It needs a running backend at `--backend` (`ws://localhost:3000` by default), Chrome at `--chrome` or `CHROME`, ffmpeg, and Piper with the voices listed in the [demo content](scripts/demo/content.js) located in `~/.cache/split-demo/piper` or at `--piper`. The videos are saved into `videos/`. Other options are described in the script, e.g. `--mute` records the video without the voice, `--no-sounds` without the key presses and clicks, `--captions` also renders the captions below the page, `--pace` changes the speed and `--show` shows the browser window for debugging, while `--phonemes` prints how the voice reads the captions and `--sounds-sample` saves an example of the sounds without recording anything. The upload guide with the titles, descriptions and chapters of the videos is generated into `videos/youtube-upload.md` by `node scripts/demo/youtube.js`.

The background pattern is generated by a [script](scripts/generate-pattern.js) with a fixed seed, so commit the regenerated `public/pattern.svg` along with the changes of the script.

The link preview image is rendered from its [SVG source](assets/og-image.svg) by a [script](scripts/render-og-image.js) using headless Chrome or Chromium, whose binary can be set by `CHROME`. Commit the rendered `public/og-image.png` along with the source and bump the image version in `index.html`, since link previews cache images by URL.

## Deployment

Every push and pull request is checked, tested and built by the [CI workflow](.github/workflows/ci.yml), and pushes to `main` are deployed to GitHub Pages. The build takes the `VITE_*` values from the repository secrets with the same names.
